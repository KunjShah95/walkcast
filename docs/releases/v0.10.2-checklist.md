## CI build (staged rollout)

`release.yml` no longer ships a tag straight to everyone. The order is:

1. `verify` → `build` (Windows + Linux).
2. `publish` creates the GitHub release **as a draft**. Drafts are invisible to
   `releases/latest/download/...`, so the in-app updater feed (`latest.json`) and the website's
   download links stay on v0.9.1.
3. `smoke` (windows-latest) installs the built NSIS installer with `/S`, boots the installed Node +
   `sidecar.mjs` on port 4399, checks `/healthz`, `/readyz`, and a clean exit on `POST /api/shutdown`,
   tries `walkcast.exe` itself on 4317 (warning only), then uninstalls silently.
4. `promote` (needs `publish` + `smoke`) runs `gh release edit vX --draft=false --latest` and checks
   `releases/latest/download/latest.json` now reports the new version.

- [ ] `verify`, `build`, `smoke`, `publish`, `promote` all green. If `smoke` fails, the draft stays a
      draft: fix, delete the draft and the tag, re-tag.
- [ ] GitHub release `v0.10.2` has `walkcast_0.10.2_x64-setup.exe`, `walkcast_0.10.2_x64_en-US.msi`,
      `walkcast_0.10.2_amd64.AppImage`, `walkcast_0.10.2_amd64.deb`, the `.sig` files and `latest.json`.
- [ ] Optional manual gate: to hold a release for hand testing, cancel the run before `promote`, test
      the draft's installer yourself, then publish with
      `gh release edit v0.10.2 --draft=false --latest`.

## Rollback

Every installed app polls `https://github.com/KunjShah95/walkcast/releases/latest/download/latest.json`,
so "rolling back" means making a known-good release `latest` again. Installs that already took the
bad version stay on it (the updater never downgrades); they get the fix as the next version.

- [ ] Stop the spread: `gh release edit v0.9.1 --latest` (re-points `releases/latest` and therefore
      `latest.json` and the website's download links at v0.9.1). Optionally mark the bad one
      `gh release edit v0.10.2 --prerelease` so it can never be picked as latest again.
- [ ] Verify: `curl -sL https://github.com/KunjShah95/walkcast/releases/latest/download/latest.json | jq .version`
      prints `0.9.1`.
- [ ] If the old release is missing its `latest.json` (or it must be re-signed), regenerate it with
      `node apps/desktop/scripts/updater-manifest.mjs <dir with v0.9.1 assets> v0.9.1` and upload it:
      `gh release upload v0.9.1 latest.json --clobber`.
- [ ] Ship the fix as v0.10.3 (a higher version is the only way to move people already on 0.10.2).

## Signing

- [ ] Windows code signing is optional and secret-gated: with `WINDOWS_CERTIFICATE` (base64 .pfx) and
      `WINDOWS_CERTIFICATE_PASSWORD` set, `build` signs the bundled `walkcast-node` exe before bundling
      and passes a `signCommand` to `tauri build` so `walkcast.exe` and the installers are signed
      before the updater `.sig` is computed. Without the secrets the run logs a notice and ships
      unsigned, as before (`docs/SIGNING.md` still describes the unsigned default).
- [ ] Confirm each updatable installer has a minisign `.sig` and `latest.json` points at v0.10.2 after
      `promote` (in-app updater).
