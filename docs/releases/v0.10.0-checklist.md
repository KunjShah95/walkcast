# v0.10.0 launch checklist

Release body: `.github/release-notes/v0.10.0.md` (published by `release.yml` via `body_path`).

## Before tagging

- [ ] `apps/desktop/dashboard/src/views/LaunchStudio.tsx` typechecks. As of this prep it does not
      (staged preset-form changes import a missing `../lib/form.ts` and contain invalid syntax),
      so `npm run typecheck` fails and the `verify` job in `release.yml` will block the release.
      Fix it or unstage it before tagging.
- [ ] Decide whether `apps/desktop/validate-presets.mjs` ships (it hardcodes `C:\browser-user\...` paths).
- [ ] `npm run lint`, `npm run typecheck`, `npm test` green (Postgres + Chrome, as in CI).
- [ ] Version is `0.10.0` in `package.json`, `package-lock.json`, `apps/desktop/src-tauri/tauri.conf.json`,
      `Cargo.toml`, `Cargo.lock` (CI fails if the tag does not match `tauri.conf.json`).
- [ ] Set the date on `## [0.10.0]` in `CHANGELOG.md`.
- [ ] Commit, then tag `v0.10.0` and push the tag.

## CI build

- [ ] `Release` workflow: `verify`, `build` (Windows + Linux), `publish` all green.
- [ ] GitHub release `v0.10.0` has `walkcast_0.10.0_x64-setup.exe`, `walkcast_0.10.0_x64_en-US.msi`,
      `walkcast_0.10.0_amd64.AppImage`, `walkcast_0.10.0_amd64.deb`, the `.sig` files and `latest.json`.

## Signing

- [ ] Installers are intentionally unsigned for the OS (see `docs/SIGNING.md`); confirm each updatable
      installer has a minisign `.sig` and `latest.json` points at v0.10.0 (in-app updater).

## Database

- [ ] Apply `supabase/migrations/20261104000000_batch_render_jobs.sql` to production Postgres
      (`npm run lab -- db migrate` or `supabase db push`) before deploying the new server.
- [ ] `walkcast doctor` shows no pending migrations.

## Smoke test (real installer build)

- [ ] Install v0.10.0 on Windows; sign in.
- [ ] Library → Select → pick 5 recordings → Render selected → 9:16. Progress counts `1/5`..`5/5`,
      result shows 5 ok, and each recording has the vertical export.
- [ ] Repeat with 1:1 on 2 recordings.
- [ ] Cancel a running batch; the Library returns to normal and a new batch can start.
- [ ] Select 11 recordings (default limit 10): the request is refused with a message naming the limit.
- [ ] In-app updater on a v0.9.1 install offers v0.10.0.

## Promote on the website (only after the GitHub release is live)

- [ ] `VERSION = "0.10.0"`.
- [ ] Add `"0.9.1"` to the front of `PREVIOUS_RELEASES`.
- [ ] Check every download URL resolves (no 404), then deploy the site.
- [ ] Commit as `fix(web): promote v0.10.0 and retain prior installers`.
